#### 2. 攻击路径 — ❌ 致命缺陷：不存在并发

**核心证据：VRP 单任务消息循环模型**

1. **`IPSEC_MsgProc`（L28920）** 是统一的消息处理入口，根据 DMS 消息接口 ID 分发：
   - IID=3 → `IPSEC_TMR_ProcMsg` → 定时器处理（包括拥塞超时）
   - IID=8 → `IPSEC_SOCKI_ProcPipeCtrlMsg` → 管道控制消息
   - 其他 → 子接口处理表

2. **`IPSEC_SOCKI_PipeMsg`** 通过 `RTF_PipeMsgProcessFuncRegister` 注册，在同一任务上下文中被 RTF 管道框架回调。

4. **`SOCK_RecvMbufEx_fl` 不阻塞**：在 VRP 管道架构中，回调仅在数据已可用时触发，`RecvMbufEx` 是内存缓冲区的直接读取，不涉及网络 IO 等待。
