# 第一步：建立攻击面地图（基于数据流分析）

3. **污点传播图谱**：每个 INPUT 的数据流树，关注每一个分叉和派生值
4. **高价值攻击点**：
   - `🟡 EXPORT` 终点 — 数据进入外部函数，**必须跟入源码检查目标函数对数据的处理是否安全**
   - `📌 USED` 终点 — 数据被用于操作，**必须检查该操作是否存在漏洞**
   - `🟢 CLEANED` 终点 — **必须验证清洗逻辑是否真正有效，能否绕过**
   - `[DEFERRED]` 终点 — 数据被存储，需评估后续使用风险
5. **数据流标注的关键发现**：★ 标记的问题
6. **子追踪**：被调用函数的内部数据流

# 第二步：源码深度审计（核心工作）

打开任务中指定的**源码目录**中的文件，逐函数、逐行审计。

## 2.1 验证并扩展数据流分析

- 验证数据流分析的每条路径在源码中的真实行为
- **主动寻找数据流分析遗漏的路径**：
  - 错误处理分支
  - 条件编译/宏展开后的隐藏逻辑
  - 回调/函数指针间接调用
  - 循环内的累积效应
  - 多线程/中断上下文的交互

## 2.2 对每个 EXPORT 终点进行安全审计

这是**最关键的分析步骤**——数据流分析只告诉你"数据传入了 func_X"，你必须：

1. 在源码中找到 func_X 的实现
2. 追踪传入的数据在 func_X 内如何被使用
3. 用完整的漏洞检查清单（见 system prompt）扫描 func_X
4. 如果 func_X 又调用更深的函数，继续跟踪（至少 3 层深度）

## 2.3 对每个 USED 终点进行漏洞模式扫描

对每个数据消费点，用你的漏洞检查清单逐项扫描：

- 作为**长度参数**：可能导致缓冲区溢出
- 作为**数组索引**：可能导致越界读写
- 作为**指针运算操作数**：可能导致任意地址访问
- 作为**比较对象**：可能导致逻辑绕过
- 作为**循环边界**：可能导致无限循环或越界
- 作为**分配大小**：可能导致整数溢出后的小缓冲区分配
- 作为**类型转换输入**：可能导致符号混淆或截断

## 2.4 对每个 CLEANED 终点进行绕过分析

数据流标记了 `🟢 CLEANED` 不代表真的安全：

- 校验条件是否完备？（`<` vs `<=`，off-by-one）
- 有符号/无符号比较是否正确？
- 是否有整数溢出导致校验失效？
- 校验和使用之间是否有 TOCTOU 窗口？
- 是否只校验了部分字段？

## 2.5 超越数据流的全局扫描

数据流分析是按 INPUT 维度组织的，你还需要：

- 检查函数中**未被数据流覆盖的代码区域**
- 查找**硬编码凭据、不安全的默认配置**
- 检查**错误处理路径**是否安全
- 检查**调用者上下文**，确认外部输入确实可达
