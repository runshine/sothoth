### 数学验证

`0xFFFFFFFD = ~0x00000002` — 所有位为1，除了bit 1

对于条件 `((v33-2) & 0xFFFFFFFD) == 0` (通过):
- 需要 `(v33-2)` 的所有位（除bit 1）都为0
- 即 `(v33-2)` 只能是 0 或 2（仅bit 1被允许）
- 因此 `v33` 只能是 **2** 或 **4**

| v33 | v33-2 | v33-2 二进制 | & 0xFFFFFFFD | 结果 |
|-----|-------|-------------|-------------|------|
| 0 | -2 (0xFFFFFFFE) | 11...110 | 11...100 | ≠0 拒绝 |
| 1 | -1 (0xFFFFFFFF) | 11...111 | 11...101 | ≠0 拒绝 |
| 2 | 0 (0x00000000) | 00...000 | 00...000 | ==0 **通过** |
| 3 | 1 (0x00000001) | 00...001 | 00...001 | ≠0 拒绝 |
| 4 | 2 (0x00000002) | 00...010 | 00...000 | ==0 **通过** |
| 5 | 3 (0x00000003) | 00...011 | 00...001 | ≠0 拒绝 |
| 6 | 4 (0x00000004) | 00...100 | 00...100 | ≠0 拒绝 |
| 7 | 5 (0x00000005) | 00...101 | 00...101 | ≠0 拒绝 |

## 触发条件
- 管道状态 v33 为 3, 5, 6, 7 等值时，数据包被丢弃

## 影响评估
- **DoS 风险**: 如果管道在某些过渡状态（非2/4）下应允许数据传输，此检查会导致数据包丢弃
- **数据流文档不一致**: 数据流分析文档声称允许 {2,3,6,7}，但实际代码仅允许 {2,4}
- **设计意图不明**: 需要参考 VRP 管道状态机文档确认 2 和 4 分别代表什么状态
- **非安全漏洞**: 过于严格的检查不会导致不安全操作，但可能导致服务质量问题
