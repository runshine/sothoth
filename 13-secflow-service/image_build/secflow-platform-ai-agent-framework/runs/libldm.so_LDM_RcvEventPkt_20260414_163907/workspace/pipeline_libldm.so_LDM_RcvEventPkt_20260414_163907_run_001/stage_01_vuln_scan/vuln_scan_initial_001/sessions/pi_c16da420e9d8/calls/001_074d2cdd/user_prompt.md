# 漏洞报告: 未检查指针算术导致越界写入 (CWE-119)

## 精确位置
- **函数名**: LDM_RcvEventPkt
- **源文件**: /home/qinghe/ai-workspace/target/libldm.so.c
- **漏洞代码行**: 第368547-368549行
- **数据流关联**: INPUT-1 (a1参数) → 结构体字段读取 → 指针算术 → 越界写入

## 漏洞类型与 CWE
- CWE-119: Out-of-bounds Write (未检查的指针算术导致内存写入越界)
- CWE-682: Incorrect Calculation (错误的指针计算)

## 严重性与置信度
严重性: High
置信度: 高
该漏洞可导致攻击者控制下的任意内存写入，取决于外部输入值。

## 源代码片段
```c
// libldm.so.c:368547-368549
if ( (*(_BYTE *)(a1 + 16) & 2) != 0
    && (v6 = *(_QWORD *)(a1 + 904), v7 = *(unsigned __int16 *)(v6 + 108), (_WORD)v7)
    && (v8 = v6 + v7) != 0 )
{
    *(_WORD *)(v8 + 180) = ProtoType;
}
```

## 完整攻击路径

### 攻击入口
- **INPUT-1**: `a1` 参数 (LDM句柄结构体指针)
- 攻击者通过控制 `a1` 指向的结构体中偏移+904处的指针和偏移+108处的16位值来利用此漏洞

### 传播路径
1. **第1步**: `v6 = *(_QWORD *)(a1 + 904)` - 从a1结构体读取扩展信息指针
2. **第2步**: `v7 = *(unsigned __int16 *)(v6 + 108)` - 从扩展信息结构体读取偏移字段(16位无符号整数)
3. **第3步**: `v8 = v6 + v7` - 指针算术运算，**无任何边界检查**
4. **第4步**: `*(_WORD *)(v8 + 180) = ProtoType` - 将协议类型写入计算出的地址

### 校验分析
- 条件 `(_WORD)v7` 仅检查v7是否非零，**不验证v7是否在安全范围内**
- 条件 `v8 != 0` 仅检查计算结果是否为NULL，**不检查是否越界**
- 攻击者可以控制v7的值，使其指向任意内存地址

### 触发点
最终触发点是向 `v8 + 180` 地址写入2字节数据(ProtoType)。
- 如果v7值很大，v8指向任意地址，可造成任意内存写入
- 如果v7值超出结构体边界，可造成缓冲区溢出

## 触发条件
1. 攻击者需要能够影响LDM句柄结构体(a1)的内容
2. 需要控制偏移+904处存放的指针值
3. 需要控制该指针+108偏移处的16位值(v7)
4. 还需要满足条件: `(*(_BYTE *)(a1 + 16) & 2) != 0` (扩展信息标志位)

## 影响评估
- **影响类型**: 任意内存写入 / 缓冲区溢出
- **后果**: 可能导致远程代码执行(RCE)、拒绝服务(DoS)或信息泄露
- **缓解措施**: 需要ASLR、DEP等现代安全机制来降低利用难度，但漏洞本身仍然可利用
