# 漏洞报告: LDM_RcvEventIPv6SrhTtlExceed 中未检查指针算术导致越界写入

## 精确位置
- **函数名**: LDM_RcvEventIPv6SrhTtlExceed
- **源文件**: /home/qinghe/ai-workspace/target/libldm.so.c
- **漏洞代码行**: 第369850-369852行
- **数据流关联**: INPUT-1 (a1参数) → 结构体字段读取 → 指针算术 → 越界写入

## 漏洞类型与 CWE
- CWE-119: Out-of-bounds Write (未检查的指针算术导致内存写入越界)
- CWE-125: Out-of-bounds Read (读取越界)

## 严重性与置信度
严重性: High
置信度: 高
与第一个漏洞模式相同，可导致攻击者控制下的任意内存写入。

## 源代码片段
```c
// libldm.so.c:369850-369852

    && (*(_BYTE *)(a1 + 16) & 2) != 0
    && (v9 = *(_QWORD *)(a1 + 904), v10 = *(unsigned __int16 *)(v9 + 108), (_WORD)v10)

    || (v11 = *(_QWORD *)(a3 + 24596)) != 0 )

}
```

## 完整攻击路径

### 攻击入口
- **INPUT-1**: `a1` 参数 (LDM句柄结构体指针)
- **INPUT-3**: `a3` 参数 (全局上下文结构体指针)
- 攻击者通过控制a1或a3结构体中的指针值来利用此漏洞

### 传播路径
1. **路径1 (a1分支)**:
   - `v9 = *(_QWORD *)(a1 + 904)` - 从a1结构体读取扩展信息指针
   - `v10 = *(unsigned __int16 *)(v9 + 108)` - 读取16位偏移值
   - `v11 = v9 + v10` - 无边界检查的指针算术
   - `*(_WORD *)(v11 + 12) = 2` - 写入到计算出的地址

2. **路径2 (a3分支)**:
   - `v11 = *(_QWORD *)(a3 + 24596)` - 从全局上下文读取指针
   - `*(_WORD *)(v11 + 12) = 2` - 直接写入(同样无边界检查)

### 校验分析
- 两个路径都缺乏对指针算术结果的边界验证
- 只检查计算结果是否为NULL (`v11 != 0`)，不检查是否越界
- 攻击者可控制v10或a3+24596的值来定位任意内存地址

## 触发条件
1. 通过异常路径(ExceptionId==22)进入此函数
2. 需要满足条件 `(*(_BYTE *)(a1 + 16) & 2) != 0` 或控制a3+24596

## 影响评估
- **影响类型**: 任意内存写入
- **后果**: 可修改任意内存位置的值，可能导致代码执行或DoS
- **利用前提**: 需要能够影响a1+904或a3+24596处的数据
