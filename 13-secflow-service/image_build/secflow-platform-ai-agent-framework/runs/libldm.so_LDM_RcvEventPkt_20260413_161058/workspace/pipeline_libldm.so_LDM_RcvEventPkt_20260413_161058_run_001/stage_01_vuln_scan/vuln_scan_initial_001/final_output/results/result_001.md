# 漏洞报告: 结构体偏移量字段缺乏边界校验导致越界内存访问

## 精确位置
- **函数名**: LDM_RcvEventPkt
- **源文件**: /home/qinghe/ai-workspace/target/libldm.so.c
- **漏洞代码位置**: 第368547-368549行
- **数据流关联**: 对应数据流分析 INPUT-1 (a1参数) 的污点传播路径

## 漏洞类型
- **CWE-119**: 数组边界外操作 - 内存读取/写入越界
- **CWE-125**: 过量读取 - 从缓冲区边界外读取数据

## 严重性
**High** - 偏移量字段 v7 从结构体偏移+108读取（长度为16位无符号整数，范围0-65535），未进行任何边界校验即用于指针运算，可能导致越界访问

## 源代码片段
```c
// libldm.so.c:368524 函数入口
__int64 __fastcall LDM_RcvEventPkt(__int64 a1, __int64 a2, __int64 a3)
{
  unsigned __int16 ProtoType; // ax
  int v5; // ebx
  __int64 v6; // rcx
  __int64 v7; // rdx
  __int64 v8; // rdx
  // ...
  
  // 第368547-368549行 - 关键漏洞代码
  if ( (*(_BYTE *)(a1 + 16) & 2) != 0
    && (v6 = *(_QWORD *)(a1 + 904), v7 = *(unsigned __int16 *)(v6 + 108), (_WORD)v7)
    && (v8 = v6 + v7) != 0 )
  {
    *(_WORD *)(v8 + 180) = ProtoType;  // 越界写入！
  }
```

## 完整数据流与攻击路径
1. **输入源头**: INPUT-1 (a1 - LDM句柄结构体指针)，该指针指向的内存区域可被攻击者控制
2. **传递路径**: 
   - a1 → 读取 a1+904 得到扩展信息指针 v6
   - v6 → 读取 v6+108 得到偏移量字段 v7 (16位无符号整数)
   - v6 + v7 → 指针运算得到目标地址 v8
3. **校验情况**: 
   - 仅检查 v7 != 0 (`(_WORD)v7` 在条件中作为真假判断)
   - **没有任何范围校验**！攻击者可以构造任意偏移量
4. **危险操作**: 
   - 读：`v7 = *(unsigned __int16 *)(v6 + 108)` - 越界读
   - 写：`*(_WORD *)(v8 + 180) = ProtoType` - 越界写

## 触发条件
- 攻击者需要能够控制 LDM 句柄结构体 (a1) 的内容
- 特别是需要控制 a1+904 指向的扩展信息结构体中的偏移量字段 (+108)
- 构造特定的偏移量值 (如 0xFFFF) 使 v8 指向任意内存位置

## 影响评估
- **任意内存写**: 攻击者可通过控制 v7 值向任意内存地址写入 ProtoType 值（2字节）
- **信息泄露**: 可通过调整偏移量读取敏感内存内容
- **拒绝服务**: 错误的偏移量可导致访问无效内存触发崩溃
- 影响范围：所有使用 LDM_RcvEventPkt 处理数据包的系统

## 补充说明：上游检查的局限性

在 LDM_DispatchProcessByProType 函数中存在对 a1+23 的有效性检查（要求值为 0xAA 或 0xCC），但该检查在漏洞触发**之后**执行，因为：

1. 漏洞代码位于 LDM_RcvEventPkt 中，执行顺序早于调用 LDM_DispatchProcessByProType
2. 指针运算 `v8 = v6 + v7` 和写入 `*(_WORD *)(v8 + 180) = ProtoType` 在进入主循环前就已执行

因此上游检查无法阻止此漏洞。

## 修复建议
1. 对 v7 (偏移量字段) 进行严格的边界校验
2. 验证 v6 + v7 + 180 不超过结构体边界
3. 添加对 v7 最小/最大值的检查（如 0 < v7 < MAX_STRUCT_SIZE）
4. 使用安全的指针运算库函数代替直接加减
