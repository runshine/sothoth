- **函数名**: LDM_DispatchProcessByProType
- **源文件**: /home/qinghe/ai-workspace/target/libldm.so.c

- **CWE-125**: 过量读取

## 严重性

## 完整数据流与攻击路径
1. **输入源头**: a1 (LDM 句柄结构体指针) 和 a3 (全局上下文指针)
2. **传递路径**: 
   - a1 → 读取 a1+904 得到扩展信息指针 v11
   - v11 → 读取 v11+108 得到偏移量字段 v12 (16位无符号整数)
   - v11 + v12 → 指针运算得到目标地址 v13
3. **校验情况**: 
   - 仅检查 v12 != 0 (`(_WORD)v12` 在条件中作为真假判断)
   - 仅检查 v13 != 0
   - **没有任何范围校验**！攻击者可以构造任意偏移量
4. **危险操作**: 
   - 读：v12 = *(unsigned __int16 *)(v11 + 108) - 越界读
   - 读：*(_BYTE *)(v13 + 17) - 越界读（访问偏移 17 处的字节）

## 触发条件
- 攻击者需要能够控制 LDM 句柄结构体 (a1) 的内容
- 特别是需要控制 a1+904 指向的扩展信息结构体中的偏移量字段 (+108)
- 构造特定的偏移量值使 v13 指向任意内存位置

## 影响评估
- **越界内存读取**: 攻击者可通过控制 v12 值读取任意内存位置的字节 (v13+17)
- **条件绕过**: 通过构造特定的内存内容，可能绕过某些安全检查 (v13+17 & 2)
- **信息泄露**: 可能读取敏感内存内容用于后续攻击
- **拒绝服务**: 错误的偏移量可导致访问无效内存触发崩溃

## 修复建议
1. 对 v12 (偏移量字段) 进行严格的边界校验
2. 验证 v11 + v12 + 17 不超过结构体边界
3. 添加对 v12 最小/最大值的检查
4. 统一在公共位置修复此漏洞模式（两个函数都存在此问题）
