请整理外部数据入口分析的输出结果。

## 步骤

### 1. 扫描函数入口报告

扫描 `{working_dir}/docker_output/` 目录，列出所有外部消息处理函数入口的分析报告。

### 2. 提取上下文信息

从输入任务描述中提取以下信息（必须传递给下游阶段）：
- **反编译源码目录**（从"上下文信息"章节获取）
- **模块名称**

### 3. 写入总结报告

将以下内容写入 `{summary_path}`：

- 分析状态
- 识别出的外部消息处理函数入口数量
- 每个函数入口的名称和简要说明

### 4. 为每个函数入口生成任务文件 ★ 关键：一对多扇出

遍历 Docker 输出中的每个函数入口报告，为每个入口在 `{results_dir}/` 下创建一个独立的任务文件。

命名规则：`result_001.md`, `result_002.md`, ... （按函数名排序编号）

每个文件的内容必须严格遵循以下格式：

```markdown
# 数据流分析任务

## 输入
- 输入文件夹: {working_dir}/docker_output/<函数入口报告文件或子目录>
- 函数名称: <函数名>
- 内容描述: 该外部消息处理函数入口的分析报告

## 上下文信息（请传递给所有下游阶段）
- 反编译源码目录: <从输入任务中继承的反编译源码目录绝对路径>
- 模块名称: <从输入任务中继承的模块名称>

## 函数入口概要
（此处填写该函数的签名、功能描述、接收的外部数据类型等）

## 任务说明
对该外部消息处理函数入口进行数据流分析，追踪外部输入数据在函数内部的传播路径、
派生变量、跨函数调用，生成完整的数据流分析报告。
```

> **重要**:
> - 每个 `result_NNN.md` 对应一个函数入口，将独立传递给下一阶段处理（扇出）
> - `上下文信息` 中的 `反编译源码目录` 必须从输入任务中原样继承，不可修改或遗漏
> - 所有路径必须使用绝对路径
