## 第一步：阅读并理解数据流分析

仔细阅读上述任务中指定的**数据流分析文件**（完整阅读，不要跳过任何部分），提取以下关键信息：

1. **目标函数信息**：函数名、所在文件、签名、功能描述
2. **外部输入清单**：所有 INPUT-N 标记的外部输入，记录其名称、类型、来源
3. **污点传播路径**：每个 INPUT 的数据流树，关注分支和派生值
4. **污点终点**：
   - 🟢 **CLEANED** — 数据被清洗，需验证清洗是否充分
   - 🟡 **EXPORT** — 数据传入外部函数，**必须跟入分析**
   - 📌 **USED** — 数据被用于操作，**必须检查操作安全性**
   - **[DEFERRED]** — 数据被存储，需评估后续使用风险
5. **关键发现**：数据流分析中 ★ 标记的问题（如返回值被忽略、校验不完整等）
6. **子追踪**：被调用函数的数据流分析详情

在心中建立完整的数据流图谱后再开始代码审计。

## 第二步：源码验证与深度分析

阅读任务中指定的**源码目录**中的相关文件（.c, .h, .asm），进行以下分析：

### 2.1 验证数据流分析结论
- 对数据流树中的每条路径，在源码中找到对应代码，确认数据确实按描述的方式流动
- 检查数据流分析是否遗漏了某些代码路径（如异常处理分支、宏展开内容等）
- 验证关键发现（★ 标记）的准确性

### 2.2 EXPORT 终点深度追踪
这是最关键的分析步骤。对每个 EXPORT 终点（数据传入外部函数的位置）：
- 在源码目录中找到目标函数的实现
- 追踪污点数据在目标函数内的处理过程
- 继续应用所有漏洞模式检查
- 如果目标函数又将数据传递给更深的函数，继续跟踪（控制在 3 层调用深度内）

### 2.3 USED 终点安全检查
对每个 USED 终点（污点数据被用于操作的位置）：
- 确认数据被用于什么操作（内存操作、比较、算术、索引等）
- 检查该操作之前是否存在充分的安全校验
- 如果存在校验，评估校验是否可被绕过
- 如果缺少校验，构造可能触发问题的输入条件

### 2.4 补充分析
- 检查数据流分析未覆盖的代码区域（如错误处理路径、条件分支的另一侧）
- 查找数据流分析之外的安全问题（如硬编码凭据、不安全的默认配置等）
- 检查函数的调用者上下文，确认外部输入确实可达
