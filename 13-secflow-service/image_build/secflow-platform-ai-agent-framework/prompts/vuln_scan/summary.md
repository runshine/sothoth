## 输出文件

### 1. `summary.md` — 综合报告

严格按照前述指令中定义的格式，撰写包含以下 7 个章节的综合报告：

1. **攻击面分析** — 目标函数功能、签名、系统角色、所有外部输入及攻击者控制能力
2. **分析覆盖度** — 含覆盖度表（数据流路径 | 起点 | 终点 | 终点类型 | EXPORT 已跟入 | 漏洞模式已扫描 | 结论）
3. **EXPORT 终点跟入汇总** — 每个 EXPORT 终点的跟入情况和发现
4. **关键发现验证** — 含验证表（数据流关键发现 | 验证状态 | 结论 | 关联报告）
5. **漏洞汇总表** — 编号 | 报告文件 | 函数 | CWE | 严重性 | 置信度 | 摘要
6. **风险评估与修复建议**
7. **局限性与未覆盖区域** — 必须诚实、具体、尽可能穷尽；上一轮未解决的未覆盖项不得静默删除，已解决则明确说明如何闭环

### 2. `results/` — 独立漏洞报告

严格按照前述指令中定义的漏洞报告格式，每个漏洞一个文件：

- 命名：`result_001.md`, `result_002.md`, ...（三位数编号，顺序递增）
- 每个报告必须包含：精确位置、CWE、严重性与置信度、源代码片段（≥5 行上下文）、完整攻击路径、触发条件、影响评估
- `results/` 目录中只保留 `result_NNN.md`

### 3. `supporting_docs/` — 辅助审计文档

若需要输出删除审计记录、USED/EXPORT 覆盖矩阵、附录、覆盖明细等非漏洞报告内容：

- 写入 `supporting_docs/`
- 不要把这些文档混进 `results/`

### 4. `previous_limitations.md` — 上一轮局限性 sidecar

- 当你完成 `summary.md` 的第 7 节“局限性与未覆盖区域”后，必须同步把该章节内容写入工作目录根的 `previous_limitations.md`
- 该文件只保存“局限性与未覆盖区域”章节内容，供下一轮返工 / global review 对照
- 若本轮已解决某项旧限制，需在 `summary.md` 第 7 节中明确说明如何闭环，并同步更新 `previous_limitations.md`

逐项确认：
- [ ] summary.md 包含全部 7 个章节
- [ ] 覆盖度表中数据流的每个 EXPORT 终点有记录
- [ ] 数据流中 ★ 关键发现全部有验证结论
- [ ] 每个漏洞报告有 ≥5 行源代码片段
- [ ] 每个漏洞有从 INPUT 到危险操作的完整攻击路径
- [ ] results/ 命名严格符合 result_NNN.md（三位数）
- [ ] summary.md 漏洞汇总表与 results/ 文件一一对应
- [ ] “局限性与未覆盖区域”章节诚实、具体、尽可能穷尽，且没有静默删除上一轮未解决项
