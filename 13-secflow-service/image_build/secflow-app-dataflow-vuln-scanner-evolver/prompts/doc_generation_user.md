## 三、生成进化文档

基于你对上述任务文件的理解和进化目标，在以下指定路径写入进化策略文档：

| 文件路径 | 注入目标 |                                                                               
|---------|---------|                                                                                 
| `{skills_worker_dir}/evolution-strategy.md` | pi-worker（漏洞挖掘者），指导任务的漏洞挖掘方向和偏好 |                             
| `{skills_advisor_dir}/evolution-completeness-review.md` | global_completeness（全面性评审），指导任务的覆盖度评审方向、偏好和标准 |       
| `{skills_advisor_dir}/evolution-depth-review.md` | global_depth（深入性评审），指导任务的深度评审方向、偏好和标准 |                     
| `{skills_advisor_dir}/evolution-result-review.md` | result_fp_check（漏洞结果误报评审），指导任务的漏洞误报判定方向、偏好和标准 |

**进化文档(方向指导)要求：**
1. **要在充分、完全地理解了当前文档要注入的目标 agent 的角色和职责的基础上进行生成**，确保内容和待注入的目标agent的职责高度相关、具有针对性且能很好的融入和配合，而不是泛泛而谈、随意发挥。
    1.1 例如：你在为 pi-worker 生成挖掘策略时，必须完全理解 pi-worker 的职责是基于数据流分析结果进行漏洞挖掘，并且它的输出会直接影响后续的评审和结果确认，那么你就需要针对这个职责，结合进化目标来设计挖掘策略，指导它应该重点关注或者忽略哪些数据流路径、漏洞模式、边界条件等，以聚焦用户的进化目标(举例：可能用户希望重点关注某一类漏洞，或者忽略某一类漏洞)。
    1.2 例如：你在为 global_completeness 生成评审策略时，必须完全理解 global_completeness 的职责是评审漏洞挖掘的覆盖度，那么你就需要针对这个职责，结合进化目标来设计评审策略，指导它应该重点关注或者忽略哪些覆盖点、数据流路径、漏洞模式等，以聚焦用户的进化目标(举例：可能用户希望重点关注某些关键路径的覆盖，或者忽略某些低风险路径的覆盖)。
    1.3 例如：你在为 global_depth 生成评审策略时，必须完全理解 global_depth 的职责是评审漏洞挖掘的深度，那么你就需要针对这个职责，结合进化目标来设计评审策略，指导它应该重点关注或者忽略哪些深挖点、数据流路径、漏洞模式等，以聚焦用户的进化目标(举例：可能用户希望重点关注某些高风险漏洞模式的深挖，或者忽略某些低风险漏洞模式的深挖)。
    1.4 例如：你在为 result_fp_check 生成误报评审策略时，必须完全理解 result_fp_check 的职责是评审漏洞结果的真实性，那么你就需要针对这个职责，结合进化目标来设计评审策略，指导它应该重点关注或者忽略哪些证据、触发条件、漏洞模式等，以聚焦用户的进化目标(举例：可能用户希望重点关注某些高风险漏洞的真实性，或者忽略某些低风险漏洞的真实性(低风险全部判定为误报)，或者某一个函数或者某一个漏洞类型全部都直接判定为误报等)。
2. 不一定要为4个角色的agent全都生成进化文档，如果你认为某个角色的agent在当前的进化目标下不需要调整策略或者没有明确的策略调整方向，那么你可以选择不为它生成进化文档；但如果你认为某个角色的agent需要调整策略或者有明确的策略调整方向，那么你就必须为它生成进化文档，不能遗漏。**总而言之：要合力服务用户提出的进化目标，而不是各自为政。**
3. 如果生成，保证生成的每份待注入文档不要超过 100 字，**直接聚焦核心进化目标**，不要写高大上的内容，保持通俗易懂(复杂和繁琐并不能起到好的效果，反而会适得其反)，指导待注入的目标 agent 的决策逻辑 & 工作方向 & 评审标准。
4. 只围绕进化目标写，不编造、不模糊、不发散。
