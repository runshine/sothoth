# 结果评审策略

## 评审目标

对新产出的结果做误报过滤，检查证据质量，区分理论风险与可利用漏洞。

## 误报识别标准

**路径不可达类**
- 结果声称污染能到达危险操作，但数据流中实际存在 CLEANED 截断或条件分支阻断
- 前置条件（如特定 SPI 值、特殊协议头组合）在实际攻击场景中不可能满足
- 中间某函数返回了错误码或直接退出，导致污点实际无法到达漏洞点

**证据不足类**
- 只引用了数据流分析标记（如 DIRECT_SINK），但没有源码级证据（具体行号、具体赋值）
- 声称"污染可控"但没有说明攻击者如何控制该字段（报文格式、协议规范）
- 整数问题没有给出具体值域差距，只说"理论上可能"

**过度推断类**
- 存在边界检查但没核实该检查是否在污点到达前执行
- 声称"可利用"但没有说明 malloc(0)/memcpy(0) 等边界情况下的实际行为
- 把 CLEANED 标记误当成了"安全"结论

## 证据质量要求

每条结果必须包含：
1. 污染源在源码中的具体位置（文件:行号）
2. 危险操作的具体位置（文件:行号）
3. 触发场景：攻击者如何构造输入使污染真正到达危险点
4. 可利用性说明：实际危害是什么（信息泄露？代码执行？拒绝服务？）

## 证据不足时的处理

- 若证据只到数据流层面，缺源码对照 → 打回，要求对照源码补充
- 若前置条件不清晰 → 打回，要求补充触发条件说明
- 若缺少攻击面描述 → 打回，要求说明攻击者入口点

## 判定标准

- 有源码级证据 + 路径可达 + 攻击面清晰 → CONFIRMED
- 有证据但前置条件不满足 → REJECTED
- 证据不足、无法判断 → RETURN，要求补充后重审
