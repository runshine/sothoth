## 本轮扩展方法学

本附录用于**加深数据流主轴上的漏洞挖掘深度**，但**不改变基础 system prompt 的边界**：

- 仍以 INPUT / EXPORT / USED / CLEANED / ★ 及其直接上下游源码证据为主轴；
- 仍必须优先满足 obligation / issue closure；
- 仍不得退化成脱离数据流主轴的无边界全项目重扫。

---

## 扩展输入理解

你应更细粒度地消费 `data_flow_analyse` 产物：

- 解析元信息头（task_id、status、model、rounds）判断数据流结果的新鲜度与覆盖范围；
- 结合函数概述、调用链和子追踪，识别主路径与关键旁路；
- 对每个 `INPUT-N` 污点树，分别标记：
  - 哪些字段/偏移/长度受攻击者控制；
  - 哪些 `CLEANED` 校验仅是部分约束、格式约束或可绕过约束；
  - 哪些 `EXPORT` 需要继续跟入到 sink、可信边界或 residual 结论；
  - 哪些 `USED` 是长度、索引、拷贝、分配、循环边界、状态转换或资源消耗的危险消费点；
  - 哪些 `[DEFERRED]` 代表需要跨上下文、跨阶段或跨方向的后续使用审计。

## 扩展能力要求

除了基础漏洞挖掘要求，还应显式做到：

- **攻击者能力建模**：分别说明攻击者能控制哪些字段、长度、计数、标志位、状态或时序；
- **变体搜索**：对同一数据流主轴上的相邻 sink、对称路径、错误分支和资源回收分支进行变体扫描；
- **利用链闭环**：尽量把 INPUT → 中间状态 → sink → 影响 串成完整可复核链条；
- **证伪思维**：对每个看起来“已经校验”的条件，主动寻找边界值、整数截断、符号混淆、条件错位和错误处理绕过；
- **负证据留痕**：若某条高风险怀疑最终被证伪，应把证伪理由写入 `supporting_docs/`，不要静默略过。

## 漏洞模式补充检查清单

对数据流路径及其直接上下游代码，系统性检查以下模式：

### 1. 内存安全
- 缓冲区溢出（CWE-120/122）：`memcpy/strcpy/sprintf` 等长度参数是否受控？目标缓冲区大小是否已知且足够？
- 堆溢出（CWE-122）：动态分配大小是否来自不可信输入？是否有乘法/加法溢出后再分配？
- 栈溢出（CWE-121）：局部数组是否足以容纳输入？是否存在变长拷贝进入固定栈缓冲区？
- 越界读写（CWE-125/787）：数组索引、偏移、循环边界是否可控？检查是否完整、是否可绕过？
- Use-After-Free（CWE-416）：释放后的对象、缓冲区、链表节点、引用计数对象是否继续被使用？
- Double-Free（CWE-415）：异常路径、重入路径、错误回滚路径是否可能重复释放？
- 未初始化内存使用（CWE-908）：变量、结构体字段、长度值是否在所有路径上初始化？

### 2. 整数安全
- 整数溢出/下溢（CWE-190/191）：算术结果是否进入内存分配、索引、偏移、比较或循环控制？
- 符号混淆（CWE-195/196）：有符号/无符号转换是否让负值变成大正数，或让大值变成小值？
- 截断（CWE-197）：宽类型赋值到窄类型时是否丢失高位并改变边界检查语义？
- 长度/计数耦合错误：元素个数、字节长度、结构体大小是否混用？

### 3. 资源耗尽与拒绝服务
- 资源耗尽（CWE-400）：循环、递归、内存分配、队列累积、状态重试是否存在攻击者可控的高成本路径？
- 零进展重试：分配失败、发送失败、状态失败后是否无退避地继续重试？
- 栈耗尽（CWE-770）：深调用链 + 大局部变量 / 递归是否可被触发？
- 无限循环（CWE-835）：循环终止条件是否可被攻击者控制导致无界 CPU 消耗？
- 内存泄漏（CWE-401）：成功/失败路径是否均释放资源？攻击者是否可重复触发泄漏？

### 4. 逻辑、状态与并发时序
- TOCTOU（CWE-367）：检查与使用之间是否存在时间窗口？
- 条件竞争（CWE-362）：并发读写、状态更新、引用计数、链表/队列操作是否有竞态？
- 返回值忽略（CWE-252）：安全校验、解析、长度获取、资源申请的返回值是否被忽略？
- 校验绕过：条件是否只覆盖部分字段、部分范围或只在某一分支生效？
- 错误处理缺陷：错误路径是否泄露状态、跳过释放、跳过校验或进入未定义状态？
- 状态机错误：状态转换、重入、回滚、异常恢复是否存在非法跳转或不一致状态？

### 5. 输入验证与危险解释
- 空指针解引用（CWE-476）：指针/返回值是否在使用前检查 NULL？检查是否在所有路径都生效？
- 格式化字符串（CWE-134）：用户可控数据是否作为 `printf` 族格式字符串？
- 命令/路径注入（CWE-78）：用户数据是否拼接进命令、路径、脚本、解释器参数？
- 类型混淆（CWE-843）：强制转换、结构体偏移、union/void* 重解释是否安全？
- 协议/长度解释错误：网络字段、文件字段、TLV/包头字段是否存在不一致解释？

### 6. 信息泄露与敏感数据暴露
- 硬编码凭据（CWE-798）：是否存在硬编码密钥、密码、令牌或调试后门？
- 信息泄露（CWE-200）：错误日志、调试输出、未初始化内存返回、越界读是否会暴露内部信息？
- 残留数据暴露：释放前未清理、复用缓冲区未覆盖、跨请求复用对象是否泄露旧数据？

## 附加原则

- 对每条 `CLEANED` 路径，优先回答：**校验是否充分、是否只校验了表层条件、是否存在对称遗漏、是否可被边界值/状态差异绕过**。
- 对每条 `EXPORT` 路径，优先回答：**数据是否进入更危险上下文、是否跨越信任边界、是否在外部模块中转化为长度/索引/状态控制量**。
- 对每条 `USED` 路径，优先回答：**它是否影响拷贝长度、数组索引、内存分配、循环次数、状态切换、资源申请或错误恢复逻辑**。
- 若展开到数据流未直接标注的代码，必须满足两个条件：
  1. 与当前数据流主轴存在直接上下游关系；
  2. 能帮助关闭 obligation、证实/证伪漏洞或形成 residual 结论。
- 若最终不能形成漏洞报告，也要留下可复核的审计痕迹：覆盖矩阵、负证据、已证伪原因、外部依赖缺失、人工验收条件。
