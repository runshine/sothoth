## 一、攻击者视角深挖（你是否已经足够像攻击者？）

### 1.1 漏洞模式覆盖
- 对你已分析的每条关键路径，回顾是否覆盖了以下所有模式：
  - 内存安全：堆/栈溢出、越界读写、use-after-free、double-free
  - 整数安全：溢出、下溢、截断、有符号/无符号混用
  - 输入验证：缺失校验、不完整校验、类型混淆
  - 逻辑缺陷：状态机绕过、条件竞争、TOCTOU
  - 资源耗尽：无限循环、内存泄漏、文件描述符耗尽
  - 密码学：时序侧信道、弱随机、常量时间比较缺失
- 如果某类模式你还没有在关键路径上尝试过，**立即补充分析**。

### 1.2 校验绕过分析
- 对路径上存在的每个安全校验（长度检查、NULL 检查、范围检查、版本检查）：
  - 是否尝试了边界值（0、1、max-1、max、max+1）？
  - 是否考虑了有符号/无符号混用导致的绕过？
  - 是否考虑了整数溢出导致校验通过但后续操作越界？
  - 是否考虑了 TOCTOU（检查和使用之间值被修改）？
- **不要看到 if 就判安全**——攻击者的工作是绕过 if。

### 1.3 跨函数深挖
- 你是否追踪了至少 3 层调用链？
- 深层函数中是否存在未被上层校验保护的危险操作？
- 回调函数、函数指针调用是否都检查了参数安全性？

## 二、已有发现的证据强化

### 2.1 证据链完整性
- 每个已报告的漏洞，是否都有：完整的 INPUT→危险操作路径、具体代码行号、触发条件、CWE 分类？
- 是否有任何结论缺少源码级证据支撑？如果有，**立即补充**。

### 2.2 遗漏的关联漏洞
- 你发现的每个漏洞，是否检查了**同类 sink family**？
  - 例如：发现一个 AH 路径的整数下溢，是否检查了 ESP 路径的同类操作？
  - 发现 IPv4 路径的问题，是否检查了 IPv6 路径的对称代码？
- 如果存在未检查的对称路径，**立即补充分析**。

## 三、行动要求

- 发现新的真实漏洞 → **立即创建新的 `result_NNN.md`**
- 发现已有报告证据不足 → **立即补充源码证据**
- 发现某类漏洞模式未覆盖 → **立即对关键路径补扫该模式**
- 若需要记录补扫范围、删除审计或覆盖矩阵 → 写入 `supporting_docs/`，供后续 summary 阶段统一整理
- results/ 文件命名 → 严格 `result_001.md`, `result_002.md`, ...
